Chapter 2: How Git Works Internally (Core Concept)
--------------------------------------------------
   - Repository
   - Working Directory
   - Staging Area
   - Commit
   - HEAD

[--------------------------------------------------------------------------------------------]

🔹Professional Definition (Important)
    - Git is a distributed version control system that tracks changes in files by creating snapshots of the project state and storing them as commits in a repository.

In simple words 👇
    - Git does not just save files, it saves the state (snapshot) of your project at different points in time.

[--------------------------------------------------------------------------------------------]

🧠 Core Idea You Must Remember

    👉 Git works in STAGES, not directly.
        <> There are 3 main areas + 1 pointer:
            1. Working Directory
            2. Staging Area
            3. Repository (Commits)
            4. HEAD (current position)

        <> Stages explaination:
            1. Working Directory: Your actual files
            2. Staging Area: Files ready to be committed
            3. Repository: Actual history of commits
            4. HEAD: Pointer to current commit

[--------------------------------------------------------------------------------------------]

🗂️ 1. Working Directory
        - The working directory is the actual folder on your computer where you create, edit, delete, or modify files.

    Simple Explanation:
        - This is your normal project folder
        - Where you write code using VS Code    


🗂️ 2. Staging Area (The Most Misunderstood Part)
        - The staging area is an intermediate area where selected changes are marked to be included in the next commit.

    Simple Explanation:
        - It is a preparation area
        - You tell Git:
            👉 “These are the changes I want to save”

    Think of it like selecting items before checkout 🛒


🗂️ 3. Repository (Commits)
        - The repository is a collection of commits that represent the history of your project.
        - A repository is a database where Git stores the complete history of commits as snapshots.

    >< Simple Explanation:
        - This is Git’s permanent memory
        - Once committed, changes are safely stored
        - This is your project history
        - Where Git stores all your commits
        - Think of it like a time machine 🕰️

    >< Each commit:
        - Has an ID (hash)
        - Has message
        - Has author
        - Has timestamp


🗂️ 4. HEAD (Current Position)
        - The HEAD is a pointer that points to the current commit in your repository.

    Simple Explanation:
        - HEAD means:
            👉 “Where am I right now in history?”

        - Like a bookmark in a book 📖


📊 FULL INTERNAL WORKING DIAGRAM

        ┌────────────────────┐
        │  Working Directory │
        │  (You edit files)  │
        └─────────┬──────────┘
                  │ git add
                  ▼
        ┌────────────────────┐
        │   Staging Area     │
        │  (Selected files)  │
        └─────────┬──────────┘
                  │ git commit
                  ▼
        ┌────────────────────┐
        │   Git Repository   │
        │   (Commit History) │
        └─────────┬──────────┘
                  │
                 HEAD

    📌 Git NEVER commits directly from working directory
    
    > It commits from staging area
    > Staging area is like a preparation area
    > You tell Git: “These are the changes I want to save”
    > Then Git commits them to the repository

[--------------------------------------------------------------------------------------------]

🌍 Real-Life Analogy (Office File System)

    Imagine you are writing a report:
        ✍️ You type content → Working Directory
        📌 You select final pages → Staging Area
        📂 You submit report → Commit
        🔖 Office keeps record → Repository
        📍 Latest approved version → HEAD

        - Staging Area = selected changes
        - Repository = permanent history
