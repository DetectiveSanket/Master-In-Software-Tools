   - git branch
   - git checkout / git switch
   - git merge
   - [Feature development practical]

[-----------------------------------------------------------------------------]

⁡⁣⁢⁣ Professional Overview⁡

    Branch commands allow developers to create independent lines of development, 
    switch between them, and merge completed work back into the main branch.

    👉 In simple words:
        These commands let you work safely, then combine work.

[-----------------------------------------------------------------------------]

🧠 ⁡⁢⁣⁣𝗖𝗼𝗺𝗺𝗮𝗻𝗱𝘀 𝗪𝗲 𝗪𝗶𝗹𝗹 𝗟𝗲𝗮𝗿𝗻⁡

    1. `git branch`   (List/Create)
    2. `git checkout` (Old Switch)
    3. `git switch`   (New Switch)
    4. `git merge`    (Combine)

[-----------------------------------------------------------------------------]

1️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝗯𝗿𝗮𝗻𝗰𝗵 (𝗖𝗿𝗲𝗮𝘁𝗲 & 𝗩𝗶𝗲𝘄)⁡

    🔹 Definition: Used to list, create, or delete branches.

    🧪 ⁡⁣⁢⁣View branches:⁡
            - git branch     <- List all local( branches that are on you machine) branches
            - git branch -r  <- List all remote branches (branches that are on GitHub)
            - git branch -a  <- List all branches (local + remote)

    ⁡⁢⁢⁣𝗢𝘂𝘁𝗽𝘂𝘁:⁡
        - ⁡⁢⁢⁢git branch⁡
            github
            * main

        - ⁡⁢⁢⁢git branch -r⁡
            origin/github
            origin/main

        -⁡⁢⁢⁢ git branch -a⁡
            github
            * main
            remotes/origin/github
            remotes/origin/main

    📌 ⁡⁣⁣⁢The `*` indicates the current branch.⁡

    🧪 ⁡⁣⁢⁣Create a new branch:⁡
        ⁡⁢⁢⁢git branch feature-login⁡

    ⚠️ Note: This creates the branch, but you are STILL on `main`.

    ## ⁡⁣⁢⁣𝗛𝗼𝘄 𝘁𝗼 𝗰𝗿𝗲𝗮𝘁𝗲 𝗡𝗲𝘄 𝗕𝗿𝗮𝗻𝗰𝗵 𝗮𝗻𝗱 𝘂𝘀𝗲 𝗶𝘁 ()⁡
        - git branch feature-login <- Create new branch
        - git switch feature-login <- Switch to new branch
        - git switch -c feature-login <- Create and switch to new branch (Recommended)

[-----------------------------------------------------------------------------]

2️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝗰𝗵𝗲𝗰𝗸𝗼𝘂𝘁 (𝗧𝗵𝗲 𝗢𝗹𝗱 𝗪𝗮𝘆⁡)

    🔹 Definition: Switches between branches or restores files.

    👉 Command:
        git checkout feature-login

    ⚠️ Why usage is declining?
    `checkout` does too many things (restoring files, checking out commits).
    Git introduced `switch` to be more specific and safer.

[-----------------------------------------------------------------------------]

3️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝘀𝘄𝗶𝘁𝗰𝗵 (𝗧𝗵𝗲 𝗥𝗲𝗰𝗼𝗺𝗺𝗲𝗻𝗱𝗲𝗱 𝗪𝗮𝘆)⁡

    🔹 Definition: Used specifically to change branches.

    👉 Switch to existing branch:
        git switch feature-login

    👉 Create AND Switch (Shortcut):
        git switch -c feature-login

    📌 This is the preferred command in modern industry flows.

[-----------------------------------------------------------------------------]

4️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝗺𝗲𝗿𝗴𝗲 (𝗖𝗼𝗺𝗯𝗶𝗻𝗲 𝗪𝗼𝗿𝗸)⁡

    🔹 Definition: Integrates changes from one branch into another.

    👉 Command (Merges 'feature' INTO 'main'):
        git switch main
        git merge feature-login

    📌 After merging, the `main` branch will have all changes from `feature-login`.
        >> TO ensure
            - git status

            ex output:

                Your branch is ahead of 'origin/main' by 2 commits.

🛠️ ⁡⁢⁣⁣𝗙𝗘𝗔𝗧𝗨𝗥𝗘 𝗗𝗘𝗩𝗘𝗟𝗢𝗣𝗠𝗘𝗡𝗧 𝗣𝗥𝗔𝗖𝗧𝗜𝗖𝗔𝗟 (𝗥𝗘𝗔𝗟 𝗙𝗟𝗢𝗪)⁡

    Step 1: Create & Switch to Branch
        git switch -c feature-message

    Step 2: Add Feature (Work)
        [Modify file...]
        git add .
        git commit -m "Add message feature"

    Step 3: Merge to Main
        git switch main
        git merge feature-message

    Step 4: Delete Feature Branch (Optional)
        git branch -d feature-message

    Q: Why not develop directly on `main`?
    A: `main` represents stable, production code. Features are experimental 
       and might break the app. Branches provide isolation.

    - Feature branches are temporary; `main` is forever/stable.
