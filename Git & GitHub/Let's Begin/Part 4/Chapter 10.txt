[-----------------------------------------------------------------------------]

 Professional Definition

    A branch in Git is a movable pointer to a specific commit that represents 
    an independent line of development.

    👉 In simple words:
        A branch is a separate path of work that does NOT disturb the main code.

[-----------------------------------------------------------------------------]

🧠 Why Branches Exist (Core Reason)

    ❌ Without branches:
        - Only one version of code.
        - Everyone edits the same files.
        - High chance of breaking the app 😵.

    ✅ With branches:
        - Safe experimentation.
        - Parallel development.
        - Clean `main` code.

    📌 Companies NEVER develop directly on main.

[-----------------------------------------------------------------------------]

🌍 Real-Life Analogy (Very Clear)

    Imagine a highway:

    - `main` branch    = Production Highway (Public, heavy traffic).
    - Feature branch   = Service Road (Construction ongoing).

    👉 You build, test, and break things on the Service Road.
       Only when it is safe do you merge onto the Main Highway.

[-----------------------------------------------------------------------------]

🧩 Core Concepts

    1️⃣ What is `main` (or `master`) Branch?
        - The default branch.
        - Represents stable, working code.
        - This is Production-ready code.

    2️⃣ What is a Feature Branch?
        - A temporary branch created to develop a specific feature or fix.
        - Examples: `feature-login`, `bugfix-navbar`, `payment-api`.
        
        📌 Rule: One feature = One branch.

[-----------------------------------------------------------------------------]

📊 Branch Tree Diagram

             main (Stable)
               │
               ├── feature-login
               │      └── commits (Work in progress...)
               │
               ├── feature-payment
               │      └── commits (Work in progress...)
               │
               └── bugfix-ui
                      └── commits (Fixing bugs...)

    👉 Each branch has its own commits and does NOT affect others.

[-----------------------------------------------------------------------------]

🧠 Important Concept: Branch = Pointer

    Internally in Git:
    - A Branch is just a pointer to a commit.
    - It is very lightweight.
    - Switching branches literally just moves a pointer.
    
    📌 That’s why Git branching is extremely fast!

[-----------------------------------------------------------------------------]

🧪 Small Practical (Check Branch)

    👉 Command:
        git branch

    Output:
        * main

    📌 The `*` symbol indicates your CURRENT branch.

        - git switch <branch-name>   <- Recommended

[-----------------------------------------------------------------------------]

🧠 When Do You Create a Branch?

    ✔ Before starting a new feature.
    ✔ Before fixing a bug.
    ✔ Before making any risky change.

    ❌ NEVER work directly on `main` in a professional setting.

[-----------------------------------------------------------------------------]

❓ Problem You Observed (Very Common)

    - “I created a new branch and pushed code, but that code is not visible on GitHub.”

    - 👉 Your understanding is partially correct, and the missing piece is branch publishing.

    🧠 Core Truth (Important)
        - ⚠️ Branches are local by default

    > When you create a branch:
        - git switch -c feature-login


    - 👉 That branch exists only on your laptop.

    - GitHub does NOT know about it yet.

    🔹 Professional Explanation

    - Creating a branch locally does not automatically create the same branch on the remote repository.
    - You must explicitly push the branch to the remote repository.

    🧩 What EXACTLY Is Missing? 
        - You are missing one thing:

    - Pushing the branch to GitHub

        🛠️ Correct Way to Push a New Branch
            Step 1: Create branch locally
                - git switch -c feature-login

            Step 2: Make changes & commit
                - git add .
                - git commit -m "Add login feature"

            Step 3: Push branch to GitHub (IMPORTANT)
                - git push -u origin feature-login


        📌 This command does 2 things:
            - Uploads branch to GitHub
            - Sets upstream (link)

🧠 What is -u (Upstream)?
    - Upstream links a local branch to a remote branch so Git knows where to push and pull by default.

    - Simple Explanation

    - After this:
        - git push


    - Git automatically knows:
        - push to origin/feature-login

    📊 LOCAL vs REMOTE BRANCH VISIBILITY

    Local Machine                 GitHub
    ┌──────────────┐              ┌──────────────┐
    │ feature-login│              │ (not visible)│
    └──────┬───────┘              └──────────────┘
        │ git push -u
        ▼
    ┌──────────────┐              ┌──────────────┐
    │ feature-login│ ───────────▶ │ feature-login│
    └──────────────┘              └──────────────┘

    🔍 How to Check Branches
        Local branches
        git branch

        Remote branches
        git branch -r

        Both
        git branch -a

    🧠 Why Git Works Like This (Design Reason)

    Git is:

    Distributed
    Offline-first

    So:
        - You can create unlimited local branches
        - Only publish when ready
        - 📌 This gives full control

    🌍 Real-Life Analogy
        Think like WhatsApp Drafts:
            Draft message → local branch
            Send message → git push
            Others can see only after sending

    ⚠️ Very Common Beginner Mistakes
        ❌ Thinking branch auto-appears on GitHub
        ❌ Forgetting -u on first push
        ❌ Pushing to main accidentally
        ❌ Editing GitHub UI without pulling locally

📝 Quick Summary (Revision Notes)
    - Branches are local by default
    - GitHub doesn’t know local branches
    - New branch must be pushed explicitly
    - git push -u origin branch-name is required once
    - After that, normal git push works
