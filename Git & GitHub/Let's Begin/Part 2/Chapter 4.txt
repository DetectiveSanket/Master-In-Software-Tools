- ⁡⁣⁣⁢A Git repository is a directory that contains a project’s files along with the complete history of changes tracked by Git.⁡

    👉 In simple words:
        - A repository is a normal folder that Git is actively watching and remembering.

    🧠 Key Question: When Does Git Start Working?

    👉 ⁡⁣⁢⁣Git does NOTHING until you initialize a repository.⁡

        >< That means:

            - Files exist ❌
            - Git tracking ❌
            - History ❌

        > ⁡⁣⁣⁢𝗚𝗶𝘁 𝘀𝘁𝗮𝗿𝘁𝘀 𝗼𝗻𝗹𝘆 𝗮𝗳𝘁𝗲𝗿 𝗴𝗶𝘁 𝗶𝗻𝗶𝘁 ⁡   


[--------------------------------------------------------------------------------------------]

🛠️ ⁡⁣⁢⁣⁡⁢⁣⁣𝗴𝗶𝘁 𝗶𝗻𝗶𝘁 (𝗕𝗶𝗿𝘁𝗵 𝗼𝗳 𝗚𝗶𝘁 𝗶𝗻 𝗮 𝗙𝗼𝗹𝗱𝗲𝗿)⁡
        - git init initializes a new Git repository by creating a .git directory that stores Git’s metadata and object database.

    >< ⁡⁣⁢⁣Simple Explanation:⁡
        - git init tells Git:
            - “Start tracking this folder”

[--------------------------------------------------------------------------------------------]

🧪 ⁡⁢⁣⁣𝗣𝗿𝗮𝗰𝘁𝗶𝗰𝗮𝗹 (𝗗𝗢 𝗧𝗛𝗜𝗦 𝗦𝗧𝗘𝗣-𝗕𝗬-𝗦𝗧𝗘𝗣)⁡

    1️⃣ ⁡⁣⁢⁣Create a new folder⁡
        - my-git-project

    2️⃣⁡⁣⁢⁣ Open terminal inside it⁡

    3️⃣⁡⁣⁢⁣ Run:⁡
        - ⁡⁢⁢⁢git init⁡

    ⁡⁣⁢⁣Output:⁡
        - Initialized empty Git repository

    🎉 Your folder is now a Git repository

    🧠 What Actually Happened?
        - A hidden folder got created:
            my-git-project/
            └─ .git/

        ⚠️ This .git folder is everything

[--------------------------------------------------------------------------------------------]

🧠 ⁡⁢⁣⁣𝗧𝗵𝗲 .𝗴𝗶𝘁 𝗙𝗼𝗹𝗱𝗲𝗿 (𝗛𝗶𝗱𝗱𝗲𝗻 𝗕𝗿𝗮𝗶𝗻 𝗼𝗳 𝗚𝗶𝘁)⁡⁡
     - The .git directory contains all metadata, objects, references, and configuration required for Git to manage version control.

    <> ⁡⁣⁢⁣Simple Explanation:⁡
        - .git = Git’s brain
        - Stores:
            - Commit history
            - Branches
            - HEAD pointer
            - Config
            - Logs

📌 If .git is deleted → Git history is gone

📂 Inside .git (High-Level View)

        .git/
        ├─ objects/     ← actual data (snapshots)
        ├─ refs/        ← branches & tags
        ├─ HEAD         ← current position
        ├─ config       ← repo settings


❌ You normally don’t touch this manually

[--------------------------------------------------------------------------------------------]

🧪 First Repository Walkthrough

    Create a file:
        index.js

    Add code:
        console.log("Hello Git");


    Now run:
        git status


    Output:
        Untracked files:
        index.js


    📌 This means:
        - Git sees the file
        - But is not tracking it yet

    This leads us directly to the next chapter 👇

## ⁡⁢⁣⁣𝗜𝗠𝗣𝗢𝗥𝗧𝗔𝗡𝗧 𝗼𝗳 𝗴𝗶𝘁 𝘀𝘁𝗮𝘁𝘂𝘀⁡

    U -> Unstracked
    M -> Modified
    S / A -> Staged / Added
    C -> Committed
    
    ## 🧠 ONE MASTER TABLE (REVISION GOLD)

        |⁡⁣⁢⁣ 𝗖𝗼𝗺𝗺𝗮𝗻𝗱                        | 𝗣𝘂𝗿𝗽𝗼𝘀𝗲⁡              |
        | ------------------------------- | -------------------- |
        | git status                      | File state           |
        | git status -s                   | Short status         |
        | git log                         | Full history         |
        | git log --oneline               | Compact history      |
        | git log --oneline --graph --all | Branch visualization |
        | git diff                        | See changes          |
        | git add                         | Stage files          |
        | git commit                      | Save changes         |
        | git restore                     | Undo changes         |
        | git reset                       | Undo commits         |
        | git branch                      | Branch list          |
        | git switch                      | Change branch        |
        | git stash                       | Temp save            |
        ----------------------------------------------------------

    🔁 ⁡⁢⁣⁣𝗡𝗢𝗪 𝗧𝗛𝗘 𝗠𝗢𝗦𝗧 𝗖𝗢𝗡𝗙𝗨𝗦𝗜𝗡𝗚 𝗣𝗔𝗥𝗧: 𝗴𝗶𝘁 𝗿𝗲𝘀𝗲𝘁⁡
        - You were right — this part is tricky and often badly taught.

    🔍 ⁡⁣⁢⁣First: View Commit History⁡
        - git log --oneline


   ⁡⁣⁢⁣ Example output:⁡
        - a1b2c3d Fix login bug
        - e4f5g6h Add auth
        - i7j8k9l Initial commit


    Each line is a save point.

    🧠⁡⁣⁢⁣ WHAT IS git reset?⁡
        - git reset moves your project back to a previous saved point

    ⁡⁣⁢⁣Like⁡:
        - Ctrl + Z (but powerful)
        - Time travel for your code

-------------------------------------------------------------------

    🔹 1️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁⁡ ⁡⁢⁣⁣𝗿𝗲𝘀𝗲𝘁⁡ <commit-hash>
            - ⁡⁢⁢⁢git reset a1b2c3d⁡


    📌 ⁡⁣⁢⁣What happens:⁡
        - Code goes back
        - Files become Modified
        - Commit removed

    🧠 Safe reset (code not lost)

-----------------------------------------------------   

    🔹 2️⃣⁡⁢⁣⁣ 𝗴𝗶𝘁 𝗿𝗲𝘀𝗲𝘁 --𝘀𝗼𝗳𝘁⁡ <commit-hash>
            -⁡⁢⁢⁢ git reset --soft a1b2c3d⁡


    📌 ⁡⁣⁢⁣What happens:⁡
        - Code stays
        - Changes stay staged
        - Commit removed

    🧠 ⁡⁣⁢⁣Use when:⁡
        - “⁡⁣⁣⁢I want to re-write commit message or combine commits⁡”

------------------------------------------------------------------------

    🔹 3️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝗿𝗲𝘀𝗲𝘁 --𝗵𝗮𝗿𝗱⁡ <commit-hash> ⚠️ DANGEROUS
            - ⁡⁢⁢⁢git reset --hard a1b2c3d⁡


    📌 ⁡⁣⁢⁣What happens:⁡
        - Code deleted
        - Changes lost

    ⁡⁣⁢> ⁣Commit gone forever⁡
        🧠 Like deleting files without recycle bin.
        🚨 NEVER use unless you are 100% sure

----------------------------------------------

    🔹 4️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝗿𝗲𝘀𝗲𝘁 --𝗵𝗮𝗿𝗱 𝗛𝗘𝗔𝗗~𝟭⁡
            - git reset --hard HEAD~1

    📌 ⁡⁣⁢⁣Meaning⁡:
        Remove last commit
        Go one step back

    🧠 ⁡⁣⁣⁢HEAD~1 = one commit before current⁡

[--------------------------------------------------------------------------------------------]

    🧠 ⁡⁢⁣⁣𝗦𝗜𝗠𝗣𝗟𝗘 𝗥𝗘𝗦𝗘𝗧 𝗖𝗢𝗠𝗣𝗔𝗥𝗜𝗦𝗢𝗡 (𝗥𝗘𝗠𝗘𝗠𝗕𝗘𝗥 𝗧𝗛𝗜𝗦)⁡

        | ⁡⁣⁢⁣𝗖𝗼𝗺𝗺𝗮𝗻𝗱     | 𝗖𝗼𝗱𝗲      | 𝗦𝘁𝗮𝗴𝗲    | 𝗖𝗼𝗺𝗺𝗶𝘁⁡  |
        | ------------ | --------- | -------- | ------- |
        | reset        | kept      | modified | removed |
        | reset --soft | kept      | staged   | removed |
        | reset --hard | ❌ deleted   ❌     | removed |

        - Git works only inside a repository
        - git init starts Git tracking
        - .git folder stores all history
        - Deleting .git removes Git
        - Files are NOT tracked automatically
