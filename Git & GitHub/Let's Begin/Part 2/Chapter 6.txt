🔹 Professional Overview
    - Core Git commands are the fundamental commands used to inspect repository status, stage changes, create commits, review history, and compare changes.

    👉 In simple words:
        - These commands let you see, select, save, and review your code changes.

    🧠 The 5 Core Commands We’ll Master
        - git status
        - git add
        - git commit
        - git log
        - git diff

    > We’ll explain each one deeply with:
        - Definition
        - Why it exists
        - Practical usage

[-----------------------------------------------------------------------------]        

⁡⁢⁣⁣𝟭️⃣ 𝗴𝗶𝘁 𝘀𝘁𝗮𝘁𝘂𝘀 (𝗠𝗢𝗦𝗧 𝗨𝗦𝗘𝗗 𝗖𝗢𝗠𝗠𝗔𝗡𝗗)
⁡     - git status displays the current state of the working directory and staging area.

    🧠 Simple Explanation
        > This command answers:
            - What changed?
            - What is staged?
            - What is not tracked?

    👉 Think of it as Git’s dashboard

    🧪 Example

            git status

            Output: 
                On branch main
                Untracked files:
                app.js
                Modified files:
                index.js


            📌 Meaning:
                - app.js → Untracked
                - index.js → Modified

            💡 When to Use
                - Before git add
                - Before git commit -> means at staging time
                - When confused 😄

[-----------------------------------------------------------------------------]    

2️⃣ ⁡⁢⁣⁣𝗴𝗶𝘁 𝗮𝗱𝗱 (𝗦𝗘𝗟𝗘𝗖𝗧𝗜𝗡𝗚 𝗖𝗛𝗔𝗡𝗚𝗘𝗦)⁡
    - git add moves changes from the working directory to the staging area.

    🧠 Simple Explanation
        > It tells Git:
            👉 “Include this change in the next commit”

    🧪 Examples

        - Add one file:
            git add app.js

        - Add all files:
            git add .

        📌 . means current folder

    ⚠️ Important Tip
        - git add does NOT save changes
        - It only prepares them

[-----------------------------------------------------------------------------]   

3️⃣ git commit (SAVING CHANGES)
    🔹git commit creates a snapshot of the staged changes and stores it in the repository history.

        🧠 Simple Explanation
            - This is the SAVE button of Git

        🧪 Example
            git commit -m "Add login feature"


        📌 Commit message should explain:
            - What
            - Why (if needed)

        🧠 Commit Message Best Practice
            <verb> <short description>


        Examples:
            - Fix login bug
            - Add user authentication

[-----------------------------------------------------------------------------]   

4️⃣ git log (HISTORY VIEWER)
    🔹 git log shows the commit history of the repository.

    🧠 Simple Explanation
        <> Shows:
            - Past commits
            - Who made them
            - When

    🧪 Example
        > git log

        - commit a1b2c3
        - Author: Sanket
        - Date: Today
        - Message: Add login feature

    📌 Press q to exit
[-----------------------------------------------------------------------------] 

5️⃣ git diff (COMPARE CHANGES)
    🔹 git diff displays line-by-line differences between file versions.

    🧠 Simple Explanation
        <> Shows:
            - What changed
            - Before commit

    🧪 Example
    git diff


    Shows:
        - Lines added (+)
        - Lines removed (-)
