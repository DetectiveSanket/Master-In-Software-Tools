[--------------------------------------------------------------------------------------------]   

Definition:
    - The Git file lifecycle describes the different states a file goes through from being created or modified to being permanently stored in the Git repository as a commit.

👉 In simple words:
    - A file changes its state as it moves from your editor to Git history.

[--------------------------------------------------------------------------------------------]    

🧠 Core Truth (Very Important)

    👉 Git does NOT track files automatically
    - Every file must earn its place in history 😄

    🧩 The 4 States of a File in Git
        - Untracked
        - Modified
        - Staged
        - Committed

Let’s understand each one deeply.

    1️⃣ Untracked
        - An untracked file is a file that exists in the working directory but is not being tracked by Git.

        >< Simple Explanation:
            - Git sees the file
            - Git is ignoring it
            - No history, no backup

        📁 Example:
            - index.js   ← new file
            - git status
            - Untracked files:
               index.js

        📌 New files are always untracked first        


    2️⃣ Modified    
        - A modified file is a tracked file that has been changed in the working directory but not yet staged.

        >< Simple Explanation:
            - File is already known to Git
            - You edited it
            - Git noticed the change

        ✍️ Example:

            - console.log("Hello Git v2");

            - git status

            - modified: index.js    

        📌 Modified files are NOT committed yet


    3️⃣ Staged (Very Important)    

        - A staged file is a file whose changes have been added to the staging area and are ready to be committed.

        >< Simple Explanation:
            - You selected the file
            - You told Git:
             👉 “Save THIS version”

        Command:
            - git add index.js

        > Now file is in staging area

    4️⃣ Committed

        - A commit is a snapshot of the project that is permanently stored in the Git repository.

        >< Simple Explanation:
            - Changes are saved forever
            - You can go back anytime

        > Command:
            - git commit -m "Add hello message"

        🎉 File is now committed

📝 Chapter 5 – Notes (Revision Ready)

        - Git files move through states
        - Untracked → not tracked
        - Modified → changed but not staged
        - Staged → ready to commit
        - Committed → saved permanently
        - git add moves file to staging
        - git commit saves snapshot
